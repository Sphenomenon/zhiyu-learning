# 登录、绑定与费用评估

核查日期：2026-09-09。结论基于下方官方公开文档；账号实际能申请的权限仍以平台审核为准。

## 当前建议

低访问量、网站优先、主体尚未确定的阶段，优先考虑手机号验证码登录，具体候选是阿里云号码认证服务中的“短信认证服务（API 版本）”。使用供应商预置签名和模板，适合不具备企业资质的个人账号。微信先作为身份绑定扩展，等网站应用权限核实后启用。此为建议，用户尚未最终选择。

这与传统“短信服务 SMS”不同：传统 SMS 支持品牌自定义签名，但当前要求企业资质报备；个人账号使用时通常需要企业授权材料。

## 费用与维护比较

| 方面 | 短信认证登录 | 官方微信网站登录/绑定 |
| --- | --- | --- |
| 前期接入 | 个人实名认证、开通号码认证服务、配置服务端接口；预置签名无需自备企业资质 | 创建网站应用、申请微信登录、通过审核、配置域名和回调；主体要求需确认 |
| 按使用量费用 | 短信按运营商成功回执计费，验证码核验免费 | 通常没有短信逐条发送费；认证/审核可能有固定费用，未核实当前报价，不写死金额 |
| 浏览器范围 | 普通手机浏览器、微信内网页、桌面网页均可使用验证码表单 | 桌面扫码、微信内网页和小程序属于不同接入场景；同一手机扫码也需要考虑操作体验 |
| 日常维护 | 验证码发送成功率、限频、防刷、余额告警、手机号变更与找回 | OAuth 回调、state、应用密钥、授权撤销、身份绑定冲突及平台规则变更 |
| 用户身份 | 验证手机号的控制权，不等于核验真实自然人身份 | 微信 OpenID/UnionID，不会自动获得手机号，也不等于核验真实自然人身份 |
| 本站采用顺序 | 建议第一版主入口 | 建议后续增加，保留账号找回入口 |

## 已查到的短信定价

阿里云[号码认证服务定价](https://help.aliyun.com/zh/pnvs/product-overview/product-pricing)的“短信认证（API 版本）”部分列明：

- 按量：每月不超过 1000 次时 0.06 元/次。
- 套餐：1000 次 54 元，折合 0.054 元/条；有效期 12 个月。
- 短信核验服务免费；短信按运营商回执状态计费，失败回执不计费。
- 套餐超额后可转按量计费，因此仍需应用内限额和云端余额告警。

例如每月 100 条，按量约 6 元/月；300 条约 18 元/月。1000 次按量在同一个月产生时约 60 元。这里是计费短信次数，不是访问次数或用户总数；重发也可能计费。保持登录可减少重复发送，不应每次打开页面都要求短信。

不要购买“通用短信服务”或“一键登录/本机号码校验”的套餐来抵扣这里的短信认证，它们的额度不互通。实际开通时重新确认购买页价格，本文不会自动同步价格变动。

## 微信能力需要分开看

1. **网站应用扫码登录**：官方开发指南要求已审核通过的网站应用、AppID/AppSecret，以及单独申请并通过微信登录审核。不能仅凭个人账号注册成功就认为能调用。
2. **微信内 H5 网页授权**：目前官方文档明确支持已认证服务号；另有已认证政府、事业单位和媒体类型公众号的特殊说明。普通个人订阅号不能按这个能力直接接入。
3. **小程序登录**：`wx.login` 是小程序专用接口，不是当前 React 网站可直接使用的接口。把它用于网站还需要另做小程序、审核及网站与小程序间的身份交接。
4. **微信支付**：是独立的商户准入与接口，微信登录成功不代表可以自动收款。

本次查阅的开放平台“应用审核规范”提到个人开发者材料及个人/非个人类目，同时包含网站信息登记表及备案要求。因此不能把“个人开发者所有微信能力一律不开放”作为准确结论。该规范也包含移动应用条款，不能反过来据此承诺个人网站扫码登录一定可以通过；待确认运营主体后，在该主体账号下核实网站应用准入。

## 账号绑定的服务端规则

- 课程和订单归属于本站 user_id；手机号、邮箱、微信身份只是附加的登录方式。
- 已登录用户在账号设置中验证新身份后才可绑定，不能按昵称或头像自动合并。
- 同一微信身份或手机号已经属于另一个账号时，显示冲突并要求验证两个账号；不直接迁移付费课程。
- 微信身份以 AppID + OpenID 标识；UnionID 仅按官方返回条件使用，不作无条件必填项。
- 换手机号要验证新号码，并对现有登录身份重新核验。无法使用旧身份时走明确的找回流程。
- 不能解绑最后一种可用登录方式；支付回调不能单凭客户端手机号决定课程归属。
- 短信请求按手机号、来源 IP、验证目的限频；验证次数和验证码有效期有限；供应商验码成功后再建立本站会话，并保证验证挑战一次性使用。
- 会话采用 HttpOnly Cookie，后台使用更严格的会话策略；手机号等信息做最小化保存和展示。
