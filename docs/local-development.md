# 本地开发与验收

更新日期：2026-09-09。本轮实现只在本地运行，未更新线上 Pages，也未创建远端数据库、短信账号或支付渠道。

## 一键启动

使用 Node.js 24 和 pnpm 11.22.0。仓库已包含依赖锁文件。

```bash
pnpm install --frozen-lockfile
pnpm dev
```

打开 `http://127.0.0.1:5173`。该命令会按顺序应用本地迁移、补充公开演示内容，然后启动 Vite 前台和位于 `127.0.0.1:8788` 的 Pages Functions。前台通过 `/api` 代理访问后端。

不用安装 MySQL、Redis、Docker 或独立短信工具。Wrangler 在本机模拟 D1 和 R2，数据库及小节插图保存在被 Git 忽略的 `.wrangler/state` 中。再次运行启动命令不会覆盖已有课程、草稿或用户数据。

开发命令明确指定 `vite.config.ts`，不会误用历史构建遗留的 `vite.config.js`。如端口已占用，请先停止占用端口的旧开发进程；启动器不会替你终止其他项目。

`pnpm dev:ui` 只启动前台，仍需可用的后端；它不再回退到演示权限。`pnpm preview` 也只是静态构建预览，不提供 API。

## 本机测试账号

进入“个人中心”，填写测试账号邮箱：

- `admin@zhiyu.local`：本机测试管理员。
- 其他邮箱格式，例如 `learner@example.com`：普通测试学员。

点击获取验证码后，验证码直接显示在本机表单上，5 分钟内有效。这里不验证邮箱所有权，也不发送邮件或短信，不能用于真实用户登录。验证码单次使用，最多尝试 5 次，同一身份 30 秒内不能重复获取。

管理员身份由本机启动配置指定，前端不能选择角色。只有同时满足 `AUTH_MODE=local`、HTTP 协议和 loopback 主机地址时，测试登录才启用。仓库的 Wrangler 默认配置为 `AUTH_MODE=disabled`；部署到 HTTPS 站点时，即使误设为 local，也不会开放测试验证码接口。

生产环境必须使用独立数据库，不能把本地测试用户、会话或假身份导入正式用户库。手机号/微信的正式身份、绑定和找回流程尚未实现。

## 手动走通一轮

1. 用测试学员登录一次，创建学员账号，随后退出。
2. 用测试管理员登录，从个人中心进入“内容管理后台”。
3. 在“课程管理”编辑课程。先保存草稿，检查公开课程尚未变化，再点击“发布到网站”。中文和英文分开编辑；课程和案例不提供英文时显示中文。首页双语为必填项。
4. 打开课程的“章节与小节”，新建章和小节，添加段落、标题和图片。需要视频的小节才填百度网盘链接及可选提取码；不需要就留空。保存草稿、预览本节后点击“发布章节”。详见 [课程编辑说明](course-authoring.md)。
5. 在“课程密钥”选择一门或多门课程，生成密钥并复制。完整密钥只在这一次响应中显示，数据库只存哈希和尾号。
6. 用另一个浏览器或无痕窗口登录学员账号，兑换密钥并进入课程，阅读图文、切换小节；有视频的地方才显示网盘入口。不要将真实资料放入自动化测试或提交到公共仓库。
7. 管理员到“学员权限”撤销这门课程，再让学员刷新阅读页，应收到无权限提示；原插图地址也不能继续读取。重试已经兑换过的密钥不会恢复被撤销的权限。

后台“学员权限”先按姓名、账号或编号搜索，选择学员后再调整权限并填写操作原因。翻页与搜索会保留选中账号；切换学员时，有未提交的原因或收款信息会先提示，确认后清空旧表单。保存成功后按钮暂时禁用，修改表单可开始下一次操作。仅在勾选“我确认已在线下收到这笔款项”并填写金额后，才创建人工收款记录。该记录不是支付平台回执，也不会发起扣款。操作编号保证同一请求重试不会重复记账。

后台编辑带版本校验。如果两位协作者同时编辑，后保存的一方会收到版本冲突提示，编辑内容会保留在表单中；复制需要保留的内容后，关闭编辑器、刷新列表再编辑。

课程下架会从公开目录移除，但不取消已有学员权限；下架后的个人中心只显示课程资料占位标题，不读取工作草稿。权限取消请使用“学员权限”。

## 后台列表与手机操作

- 学员：搜索姓名、账号或账号编号，可筛选学员/管理员角色；从列表选择具体账号，当前账号会在权限表单上方持续显示。
- 密钥：按尾号搜索，可筛选待兑换、已兑换、已停用和已过期；兑换截止或课程访问截止任一已过，均显示已过期。完整密钥仍只在生成时返回。
- 收款：按学员姓名、账号、编号或收款备注搜索，记录显示学员名称和课程名称。
- 列表每页 20 条，显示匹配总数；搜索与筛选回到第一页，空页会回到最后一个有效页。加载中、无匹配和请求失败分别显示，失败后可重试。
- 手机后台的六个入口分两行显示并保持在滚动顶部；搜索、筛选、分页及编辑按钮适配窄屏，输入字号保持 16px。

三个管理列表接口保留 `items`，新增 `pagination: { page, pageSize, total }`。支持 `q`、`page` 和 `pageSize`（默认 20、最大 100）；学员接口还支持 `role=all|student|admin`，密钥接口支持 `status=all|available|redeemed|revoked|expired`。无效参数返回 400，未登录/非管理员分别返回 401/403。

新增 `0003_admin_list_indexes.sql` 为按时间和角色读取增加索引，下次 `pnpm dev` 会自动应用。关键词采用字面子串匹配，中文可直接搜索，英文不区分大小写；分页按创建时间降序、ID 升序排列。并发新增记录可能让不同次翻页间的位置移动，刷新第一页可查看最新记录。

## 自动化检查

```bash
pnpm build
pnpm test
```

- `test:backend`：建立独立临时 D1，在真实本地 Workers 运行时中检查会话、重复验证、CSRF、资料隔离、并发兑换、撤权、草稿发布、版本冲突、人工收款幂等和第二次登录的账号一致性。
- `test:ui`：使用 DOM 环境检查登录、兑换失败、管理员入口、私有资料拒绝、草稿/发布以及主题和语言切换。
- 后台列表测试额外创建 225 个虚构学员和 225 条不可兑换的测试密钥，验证超过原 200 条上限的分页、搜索字面值、两种截止时间和权限隔离；这些记录只进入临时测试数据库。
- 新增 DOM 检查覆盖选择学员后的翻页、搜索与权限提交、收款重试、切换学员、过时请求、加载失败重试、状态筛选和末页变化。
- 章节检查额外覆盖草稿隔离、公开目录字段、付费正文权限、私有 R2 上传与图片读取、无影片小节、版本冲突、撤权和暂停发布；UI 检查覆盖图文编排、分享文字识别、上传、发布、复制提取码、深链接及语言回退。
- 后端测试为验证真实的重复获取限制，会等待约 31 秒。测试结束清理的是临时测试目录，不是开发数据库。
- UI 测试不是手机或桌面浏览器的像素截图验收。实际手机布局、系统键盘和网盘跳转仍需真机检查。

2026-09-09 本机验收：构建通过，32 项后端测试、26 项 DOM 测试通过；浏览器检查了 320px、390px 和 1280px 视口的后台导航、学员表单、密钥表单、课程编辑弹窗，以及中英文和亮暗主题。修复了 320px 窗口带滚动条时的横向溢出。课程功能另已通过浏览器创建两章三节演示，上传图片、保存草稿、发布、进入课程、展开目录并跨章切换；检查 320px、390px 和 1280px 的编辑及阅读布局。阅读页同样修复了窄屏带滚动条时的横向溢出。该检查使用桌面浏览器调整视口，尚不替代真实手机测试。

GitHub Actions 在 push 时运行构建和测试；另有手动 Deploy to Cloudflare Pages 工作流，配置要求和发布步骤见 [部署说明](deployment.md)。

## 代码入口

| 位置 | 用途 |
| --- | --- |
| `functions/api/[[path]].ts` | Pages Functions 入口 |
| `server/router.ts` | API 路由与统一错误处理 |
| `server/auth.ts` | 测试身份适配、会话、角色检查 |
| `server/access.ts` | 密钥、权限、私有资料、人工收款 |
| `server/admin-lists.ts` | 后台搜索、筛选与分页 |
| `server/curriculum.ts` | 私有章节、小节图文、可选影片与受控插图上传/读取 |
| `src/CurriculumEditor.tsx` / `src/LearningView.tsx` | 章节编辑器与学员阅读页 |
| `server/content.ts` | 公开字段校验、双语内容、草稿与发布 |
| `migrations/` | 数据库结构、原子兑换触发器、幂等操作记录 |
| `src/Account.tsx` | 学员登录、兑换、资料领取 |
| `src/Admin.tsx` | 内容编辑与后台导航 |
| `src/AdminAccess.tsx` / `src/AdminRecords.tsx` | 学员、密钥、收款表单和通用搜索分页 |
| `src/AppBusiness.tsx` | 保留现有品牌风格的公开页面与导航 |
| `src/catalog.ts` / `src/data.ts` | 公开演示种子，不含私有资料 |

业务状态不再读取历史 `zhiyu-access`、`zhiyu-content` 或 `zhiyu-stories` 的 localStorage。原型中的本机修改不会自动迁入数据库。旧键值无需删除；当前仅使用 localStorage 记住主题与语言。

## 上线前仍需完成

- 确认运营主体、主登录方式与实际收费流程，再接入正式供应商；配置实名登录、管理员初始化和找回流程。
- 建立远端 D1，替换 `wrangler.jsonc` 的占位数据库 ID，并应用迁移。不要把本机登录模式发布为正式身份方案。
- 配置真正的课程、价格、联系信息、案例授权与素材。当前仍保留知识管理示例文案，尚未确认最终吉他课程内容。
- 小节图片已接入私有 R2 上传，正式环境需创建并绑定 `COURSE_IMAGES`，保持桶私有；数据库与图片存储都需要备份。本地启动不会创建远端桶。
- 封面仍用地址与预览，首页/讲师主图仍为现有素材；这些位置的上传与替换表单尚未开放。删除草稿图文块不会清理对象存储，后续需实现未引用图片的保留与清理规则。
- 学员投稿、手动学习进度、身份绑定、自动支付、退款及自动对账尚未开放。
- 进行真机和目标网络验收，落实备份恢复、日志保留期限、监控及隐私说明。当前内容列表按站点规模读取；学员、密钥和收款记录已提供搜索分页。大规模站点的全文搜索和深页查询仍需专项性能评估。
- 确定账号和域名归属后，再由运营者完成供应商需要的实名、认证、收款账户和相关材料；具体办理项见后端方案，不提前购买服务。
